# Instructions for AI agents working in this repo

This repo is a public, collaborative **reading** of the Lean proof of the Riemann Hypothesis. Lean has already checked the proof, so nobody here re-proves anything. The work is explaining what each file does, why the proof needs it, and how it connects.

## The source is read-only

The Lean code lives in **another** repo: <https://github.com/leanprover-community/riemann-hypothesis>. It is pinned at commit `a7231db2ec4917f8c63b88c2e09bfc2086e3f613`, and that commit is in `map.json`.

- **Read it, never change it.** Don't open pull requests, issues or comments on that repo, and don't push to it. Its maintainers want Lean clean-ups, not explanations. Only a person, acting for themselves, contributes upstream.
- **Never build it.** Don't run `lake build`, `lake exe cache get`, `lean`, or anything that compiles the proof. A build takes hours and over 24 GB of memory, and reading needs none of it.
- **In a HiveOp box, the source is already there.** The workspace links `Wenrwa/riemann-hypothesis-source`, a read-only mirror of the community repo at the pinned commit. HiveOp checks it out next to this repo, and your workspace notes give its path. Read it there. Don't commit to it or push to it.
- Elsewhere, use the GitHub links in `parts/*.json` (field `url`), or make a blob-less clone, check out only the files you need, and treat it as read-only:

```
git clone --filter=blob:none --no-checkout https://github.com/leanprover-community/riemann-hypothesis.git /tmp/rh-src
cd /tmp/rh-src && git checkout a7231db2ec4917f8c63b88c2e09bfc2086e3f613 -- src/New/Reduction/Zeros/Criterion.lean
```

- Good orientation: the source's `GUIDE.md` (structure and glossary), `INDEX.md` (the final chain of theorems) and `CONTENTS.md` (every file, with its title). Each Lean file opens with a note by its authors, its "head". Start there.

## What to write here, and how

You change **only** `readings/` and `status.json`. Everything else (`map.json`, `parts/*.json`) is generated by `tools/extract.mjs`, so don't edit it by hand.

**Explain one file per work item:**

1. Read the file's head and its Lean. Check `parts/<part>.json` for its `uses`, `usedBy` and `role`.
2. Write `readings/<path with / replaced by __>.md`. For example, `src/New/Reduction/Zeros/Criterion.lean` becomes `readings/src__New__Reduction__Zeros__Criterion.lean.md`. Use these sections:
   - **What it is:** what the file proves, in plain words (2 to 5 sentences).
   - **Why the proof needs it:** what it feeds, using `usedBy` and the part's story.
   - **How it does it:** the main steps, naming the key theorems in `backticks`.
   - **Background:** the textbook or paper, if the file's head names one.
   - **In one line:** a single sentence anyone could follow.
3. Add the file to `status.json`: `"<path>": { "by": "<your agent name> (AI agent)" }`.
4. Open a pull request to this repo. Its title is `Explain <short path>`, and its body lists what you were unsure about.

**Rules:**

- **Say only what the Lean says.** If you are unsure, write "I think" or "unclear", and never invent. Quote names exactly.
- **Never mark anything confirmed.** Only a person sets `confirmedBy`, after reading the Lean themselves.
- **Never call the proof refereed or "fully understood".** Its scope is ζ and Dirichlet L-functions.
- **Credit others.** If a guide (listed per part in `stories.json`, field `elsewhere`) explains this part, link it rather than repeating it.
- **One file per pull request.** Keep the diff to that reading plus its `status.json` line.

## Checking the site locally (optional)

`python3 -m http.server 8000`, then open `http://localhost:8000`. The site reads `status.json` and `readings/` live.
